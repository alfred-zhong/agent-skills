## 5. 实际可能出错的边界情况

测试过程中发现以下场景在 SKILL.md 现有覆盖下**可能出错的边界情况**：

### 5.1 表格行内代码混排

样本表格有 `- **是什么**：` 这种"加粗 + 冒号"的混合。agent 拿到这种行内格式时，SKILL.md §4.1 只演示了"段落 + 粗体 + 行内代码"，没演示"段落 + 粗体 + 冒号"。

**建议补**：§4.1 增加"- **粗体引导**：普通文本"模式的 JSON 示例。

### 5.2 列表项里含换行

`- **是什么**：产品 interrogation 工具。6 个强迫性问题帮你重新定义产品方向。\n- **干什么**：挑战你的问题框架、质疑前提假设...`

agent 拿到这种 list item 时，不知道 `**是什么**` 后面的换行是该保留成 `\n` 还是该拆成多段。SKILL.md §3 CreateRichText 没明说 string 内的 `\n` 怎么渲染。

**建议补**：§3.1 RichText 字符串里 `\n` 的渲染规则（推测：会作为软换行处理；需 wolai 渲染验证）。

### 5.3 列表与段落的混合层级

样本 `- **是什么**：` 这种"列表项里嵌入行内粗体 + 段落"是 md 里极常见模式，但 SKILL.md §4 只覆盖纯列表，没演示"列表项里含行内富文本"。

**建议补**：§4 增加一行：`bull_list` 块的 `content` 可用 RichText 数组，演示"- **粗体**：说明文字"模式。

### 5.4 Code block 风格 vs 行内代码

样本用 `**是什么**` 加粗而非 `` `是什么` `` 行内代码。SKILL.md §4.1 演示了行内代码 + 加粗混排，但实际样本里**几乎没有**行内代码（除了一些 ` `/path` ` 路径）。**说明 SKILL.md §4.1 的例子偏向"开发者文档"风格，对"产品描述"风格的 md 覆盖不够。**

**建议补**：§4.1 增加"产品描述风格"完整示例（粗体引导词 + 普通段落）。
