# route-cp：给轨迹标 CP 点并导出 GPX

输入一条轨迹，输出带 CP 路径点的 GPX，外加一张 CP 表（里程 / 海拔 / 累计爬升 / 站间距离）。

## 为什么默认出 GPX，而不是 KML

**华为运动健康的「导入路线」只吃轨迹线，KML 里的 `<Placemark><Point>` 一律不显示；GPX 的 `<wpt>` 才会被识别成路径点。** 2026-10-16 实测：同一份灵白线，GPX 的 7 个 CP 在华为运动健康里全部可见，KML 版一个都不显示（原文件的 19 个标注点在 KML 里同样不显示）。

所以：**交付默认给 GPX**。只有当用户明确要在 Google Earth / 两步路里看图时才加 `--format kml`。

## 步骤

1. **确认输入文件**。用户手上的轨迹多半是两步路导出的 KML（几何是 `gx:Track`，个别是 `LineString`），也可能是 GPX。不确定就先读文件头确认几何类型。
2. **跑脚本**：
   ```bash
   python3 <skill_dir>/scripts/route_cp.py <输入轨迹> [-o 输出目录] [参数]
   ```
   脚本自动识别 `gx:Track` / `LineString` / GPX `trkpt`，输出 `<原名>_CP.gpx`。
3. **核对输出**：脚本会打印 CP 表和站间距离，并用 `xmllint` 校验 XML 良构。**逐行看一遍选点是否落在真实的地形特征上**——如果出现连续多个「里程点」，说明 `--prominence` 偏高或 `--max-gap` 偏小，按需调参重跑。
4. **交付**：给出 GPX 的绝对路径 + CP 表（Markdown 表格），并说明「华为运动健康里 GPX 才认 CP」。

## CP 选点规则（脚本内已实现）

按地形取点，不做等分。优先级从高到低：

| 优先级 | 取点 | 判据 |
|---|---|---|
| 1 | 起点、终点 | 必设；首尾相距 < 300 m 视为环线，合并成「起点 / 终点」 |
| 2 | 峰 | 邻域（默认 ±600 m，路线短时自动收窄）内的最高点，且与邻域最低点高差 ≥ `--prominence`（默认 50 m） |
| 3 | 中途最低点 | 排除首尾各 15% 后的最低点——即最后一段长爬升的起点。首尾本身就是全线最低点时不会误取 |
| 4 | 里程点（补点） | 相邻 CP 间距 > `--max-gap`（默认 2000 m）时，在中间按等距补 |

峰按**行进顺序**编号（第 1 峰 = 第一个山头），最高的那个额外标成「全线最高点」。

## 里程与爬升口径

- **里程**：三维（水平距离 + 高程差）累计，与两步路口径一致（灵白线 9.01 km 对得上官方的 8.98 km）。
- **爬升**：先对高程做 ±50 m 滑动平均，再累加正向增量。直接用原始高程累加会被 GPS 高程噪声虚高（灵白线 642 m vs 真实 561 m）。
- **峰谷判定**另用 ±100 m 平滑，抗单点噪声。

## 常用参数

完整列表见 `python3 scripts/route_cp.py --help`。最常调的三个：

| 参数 | 用途 |
|---|---|
| `--max-gap` | CP 最大间距。9-10 km 的轻越野用 2000 m；马拉松级路线用 3000-5000 m |
| `--max-cps` | CP 数量上限（默认 10）。超了就删得分最低、且删后不破 `--max-gap` 的点 |
| `--prominence` | 峰谷显著性阈值。山丘密集的路线调低（如 30），平缓路线调高（如 80） |
| `--format` | `gpx`（默认）/ `kml` / `both` |

## 已知边界

- **轨迹没有高程**（`<ele>` 缺失或全 0）：只能出「起点 / 终点 + 里程点」，峰谷检测失效。
- **短路线上的密集小丘**（山丘间距接近判定窗口、高差又不足 `--prominence`）可能被并成一个峰。调低 `--prominence` 或 `--window` 可拆开。
- **输出的 GPX 一定是完整的**：`<wpt>` 在前、`<trk>` 在后，含全部原始轨迹点，可直接被华为运动健康 / 两步路 / Garmin 读取。
